# 02 ローカル起動手順書

[01 ローカル環境構築書](01_ローカル環境構築書.md) が終わっている前提で、毎日の起動・停止の手順をまとめます。

## 1. 起動する

PowerShell（または VS Code のターミナル）で：

```bash
cd C:\workspace\jikanwari
```
```bash
npm.cmd run dev
```

`✓ Ready` と表示されたら、ブラウザで開きます。

- 開発用：http://localhost:3000
- 「ゲストとして試す」を押すと時間割画面に入ります

> パッケージが変わったとき（`package.json` や `package-lock.json` が更新されたとき）は、先に `npm.cmd ci` を実行します。`npm.cmd install` は使わないでください（[よくあるエラー](#6-よくあるエラーと対処)）。

## 2. 停止する

起動したターミナルで `Ctrl + C` を押します。

## 3. 作業前に最新のコードにする

```bash
git checkout develop
```
```bash
git pull
```
その日の作業ブランチ（`feature_vN`）を作る手順は [08 運用手順書](08_運用手順書.md) を参照してください。

## 4. テスト・チェックを実行する

| やること | コマンド | 成功の目安 |
|---|---|---|
| 自動テスト | `npx.cmd vitest run` | `Tests  NN passed` |
| 型チェック | `npx.cmd tsc --noEmit` | 何も表示されない |
| 本番用ビルド | `npx.cmd next build` | `○ (Static)` などの一覧が出る |

> 本番用ビルドは開発用サーバーを止めてから実行してください（同じ `.next` フォルダを使うため）。

## 6. よくあるエラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| `npm : このシステムではスクリプトの実行が無効…` | PowerShell の実行ポリシー | `npm.cmd` / `npx.cmd` を使う |
| 画面が 500 エラー、ログに `ENOENT … .next\server\…` | 開発中にブランチを切り替えて `.next` が壊れた | 下の「キャッシュの削除」を行う |
| 画面が「読み込み中…」のまま | 古いキャッシュ／ブラウザに古い画面が残っている | ブラウザで再読み込み（F5）。直らなければキャッシュの削除 |
| `Port 3000 is in use` で 3001 番で起動する | 前の開発用サーバーが残っている | 残っているサーバーのターミナルで `Ctrl + C`。見つからなければPCを再起動 |
| テストで `Cannot find module './rolldown-binding…'` | `npm install` で `package-lock.json` から Windows 用の部品の記載が消えた | `git checkout -- package-lock.json` で戻してから `npm.cmd ci`（開発用サーバーは止めておく） |
| ログインで `anonymous_provider_disabled` | Supabase で匿名ログインが無効 | 01 の 4-2 を確認 |
| AIのボタンが押せない（「APIキーが未設定」） | `ANTHROPIC_API_KEY` が空 | `.env.local` に設定し、開発用サーバーを再起動 |
| AIのボタンが押せない（残り0回） | 1日の上限に達した | 日本時間の翌日まで待つ（[08 運用手順書](08_運用手順書.md)） |

### キャッシュの削除

```bash
Remove-Item -Recurse -Force .next
```
```bash
npm.cmd run dev
```
