# 01 ローカル環境構築書

開発用のパソコン（Windows 11 を想定）で、本アプリを動かせる状態にするまでの手順です。最初の1回だけ行います。

## 1. 用意するもの

| 種類 | 名前 | バージョン・備考 |
|---|---|---|
| ソフト | Node.js | 22 以上（動作確認：24.8）。https://nodejs.org の LTS 版 |
| ソフト | Git | 最新版。https://git-scm.com |
| ソフト | エディタ | VS Code など |
| ソフト | ブラウザ | Microsoft Edge / Google Chrome |
| アカウント | GitHub | ソースコードの管理 |
| アカウント | Supabase | データベース・ログイン（無料プラン） |
| アカウント | Vercel | 公開（無料の Hobby プラン）。ローカルだけなら不要 |
| アカウント | Anthropic（Claude API） | AI機能（疑似テスト・志望校調査）を使う場合のみ。有料 |

## 2. ソースコードを取得する

```bash
cd C:\workspace
```
```bash
git clone https://github.com/tetsu4993/juku-timetable.git jikanwari
```
```bash
cd jikanwari
```

## 3. パッケージをインストールする

```bash
npm.cmd ci
```

> `npm.cmd ci` は `package-lock.json` のとおりに入れ、ファイルを書き換えません。`npm.cmd install` は Windows 用の部品の記載を消してしまうことがあるため、普段は使いません（パッケージを追加・更新するときだけ使い、テストが動くことを確認してからコミットします）。

> PowerShell では `npm` / `npx` ではなく `npm.cmd` / `npx.cmd` を使います。Windows の初期設定ではスクリプト（`.ps1`）の実行が禁止されているためです。設定を変える必要はありません。

## 4. Supabase のプロジェクトを用意する

1. https://supabase.com でプロジェクトを作成する（リージョンは Tokyo を推奨）
   - データベースのパスワードは控えておく（7. で使う）
2. **Authentication → Sign In / Providers** で **Anonymous sign-ins（匿名ログイン）** を有効にする
   - 「ゲストとして試す」で使います
3. **Project Settings → API Keys** で次の値を確認する
   - Project URL（`https://xxxx.supabase.co`）
   - Publishable key（`sb_publishable_...`）
   - Secret key（`sb_secret_...`）または Legacy タブの service_role

## 5. 環境変数ファイル `.env.local` を作る

プロジェクト直下の `.env.example` をコピーして `.env.local` を作り、値を入れます。

```bash
Copy-Item .env.example .env.local
```

| 変数名 | 値 | 用途 | 秘密 |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL | DB・ログインの接続先 | 公開してよい |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key | ブラウザからの接続（RLSで保護） | 公開してよい |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret key | サーバー側のデモリセット・AI回数管理 | **秘密** |
| `CRON_SECRET` | 自分で決めた長い英数字 | 毎日のデモリセット（Vercel Cron）の合言葉 | **秘密** |
| `ANTHROPIC_API_KEY` | Anthropic の API キー | AIの疑似テスト・志望校調査。空なら AI 機能は無効 | **秘密** |

> `.env.local` は `.gitignore` に入っているので GitHub には上がりません。秘密の値をチャットや画面共有に貼らないでください。

## 6. Supabase CLI でプロジェクトにつなぐ

```bash
npx.cmd supabase@2.58.5 login
```
ブラウザが開くので許可します。

```bash
npx.cmd supabase@2.58.5 link --project-ref <プロジェクトID>
```
`<プロジェクトID>` は Project URL の `https://xxxx.supabase.co` の `xxxx` 部分です。データベースのパスワードを聞かれたら入力します。

## 7. データベースを作る（マイグレーション）

`supabase/migrations/` の SQL を番号順に適用します。

```bash
npx.cmd supabase@2.58.5 db push --linked
```

確認：

```bash
npx.cmd supabase@2.58.5 migration list --linked
```
Local と Remote の両方に `0001`〜最新番号が並んでいれば完了です。

## 8. デモデータを入れる

Supabase の **SQL Editor** で次を実行します（アプリ起動後に画面左下の「デモデータを初期状態に戻す」を押しても同じです）。

```sql
select reset_demo();
```

先生5人・生徒70人・コマ5つ・通常期と夏期講習・曜日テンプレート・定期テスト4回分・学校と教材などが入ります。

## 9. 動作確認

[02 ローカル起動手順書](02_ローカル起動手順書.md) に従って起動し、http://localhost:3000 で「ゲストとして試す」を押して時間割が表示されれば完了です。
